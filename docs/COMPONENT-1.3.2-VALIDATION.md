# 1.3.2 完整默认数据库与解析引擎交付

默认规范库和引擎均在同一 Release 中提供，不再依赖用户到旧发布页寻找配套 ZIP。用户下载 EXE、1 个引擎 ZIP 和 3 个数据库 ZIP，放在同一文件夹后启动即可自动校验、安装和登记资料。

默认数据包含 71 份 PDF 原件；冻结资源快照中 66 份已经解析并带 SQLite 索引，另外 5 份保留原件并自动后台 OCR。分组「施工验收规范」默认建立，个人材料可追加到新分组。公开目录位于 `specflow-component/presets/施工验收规范目录.csv`。数据库包不包含用户设置、API 密钥、会话、聊天附件或个人导入的资料。

引擎包含独立 CPython 3.12.7、MinerU 3.4.5、CPU PyTorch 2.14.0、全部默认 OCR/版面/表格模型、FastText 语言模型及 Windows 本地运行库。其源码、模型和规范继续保留各自许可。

65 项 Node 测试通过。新增检查覆盖默认分组去重、数据库升级保留用户修正、路径规范化和归档越界拒绝。数据库升级只填补缺失的用户资料库文件，预置目录元数据可以更新；已有 API 设置、会话和自建资料不覆盖。

在完全空的新目录，仅放 EXE 和四个 ZIP，使用 `--offline-resources` 禁止缺包时联网下载。实际由 EXE 解压全套资料与引擎，默认登记 71 份原件、66 份预建索引，没有继承开发电脑的设置、密钥或会话。样本查询返回 8 个带原文坐标的命中，耗时 110 ms。追加测试 PDF 后文档总数为 72，原默认分组仍为 71。随新包解压的 CPU 引擎实际解析并保存了 8 页检查点；其 Python 模块路径均位于新目录，不引用 Anaconda 或开发环境。完整过程用时 426.7 秒。

最终 EXE 另通过独立启动、真实文字 PDF 上传与检索、PDF 范围读取和定位、流式事件、两轮上下文，以及模型配置和会话重启保留检查。

大型资源可通过 GitHub 手动工作流重建：从既有固定基础资源与小型差量生成，逐条校验压缩成员及整包 SHA256，结果与本机完整离线验收使用的 ZIP 逐字节一致。该工作流只写入指定草稿 Release，不会替换已公开资源，也不会读取个人资料库或 API 配置。
