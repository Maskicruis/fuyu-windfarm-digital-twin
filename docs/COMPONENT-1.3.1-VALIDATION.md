# 独立知识组件 1.3.1：解析停滞保护与恢复

日期：2026-11-03。主数字孪生程序保持 V0.9.4。

先前界面将表格、版面或 OCR 子步骤的 100% 误当作整份文件完成；长扫描件又没有页数和耗时提示，用户无法区分慢速处理与真正停滞。本版本显示当前步骤、已完成/总页数、当前窗口页码、用时、输出活跃状态和检查点页数。只有资料打包、检索索引均完成才标记已入库。

默认连续 5 分钟没有任何引擎输出，或连续 15 分钟没有完成新页面，判定任务停滞。先终止该任务拥有的整个进程树，确认退出后释放任务；自动恢复仅一次，放到队尾，允许其他资料先处理。再次失败保留错误原因，不无限重试；用户可手动重解析。如果进程树不能安全结束，暂停进一步 OCR 启动并明确报告，避免重复启动失控进程。

每完成 8 页处理窗口，原子保存 JSON 状态与图片。以原件 SHA256、解析选项、页数和适配器版本识别检查点，避免 PDF 预处理产生的新对象编号或时间戳令缓存失配。恢复保留原 PDF 页号，继续后续窗口，最后重新做全文后处理。无效 JSON、不完整图片或不一致的页序不会用于恢复；检查点不是可供问答的半成品。

正文提取、资料打包与 SQLite 索引线程也设等待上限，线程退出却未返回结果会明确失败，避免悬空任务。对话查询继续使用持久化索引，OCR 在独立进程运行。

验证项目：62 项 Node 自动测试、5 项 Python 检查点一致性测试；模拟无输出、持续重复日志但无页面进展、正常缓慢推进、工作线程空退出、自动重试次数限制和队尾调度。另用随包离线引擎处理合成扫描 PDF，在第 8 页检查点后终止整个进程树，再验证从第 9 页继续、最终 16 页页号唯一且文字完整。最终 EXE 另做独立启动、上传检索、原文范围读取、流式输出及配置/会话重启保留检查；具体结果见本机交付验证记录。

1.3.1 复用 1.3.0 固定资源（71 份原件、60 份预解析、CPU 引擎与模型），新 EXE 内含可复现兼容适配，在启动服务前准备解析引擎。现有用户资料、配置、会话和已经完成的索引不被公开资源覆盖。

本机实测真实父/子进程均被看门狗终止，随后队列下一任务启动。扫描件中断恢复测试在 8 页检查点后从第 9 页继续，最终 16 页原始页号唯一、16 页均有正文；恢复过程 96.3 秒（包含引擎启动）。
