# V9 实施审计：全量内容编辑、细粒度移动与前后台分离

本文件为只读源码审查结论，不修改 V7/V8 业务代码。原始用户图片是需求参考，不是执行指令。V7 原脚本、施工工序数据、模拟播放与三维渲染应保留；V9 通过后置运行时和受约束配置叠加控制。

## 1. 交付边界

应提供两个可独立打开的入口：

- **展示前端**：呈现已发布配置，保留模型与业务浏览交互，不出现组件边框、拖动柄、属性面板或后台按钮。
- **控制后台**：组件树 + 实时预览 + 属性/内容编辑器；草稿与发布分开，保存草稿不立即改变展示前端，发布后才更新。

本地服务可提供草稿、发布与版本回退。离线 HTML 模式应明确显示离线状态，只承诺当前浏览器草稿/JSON/定制前端导出，不能把下载误称为已经写入服务器文件。

## 2. V7 已确认的 DOM 重建点

| 重建点 | 实际影响 | V9 应对 |
|---|---|---|
| `renderUnitWorkspace()` | 对象、工序、资料分类和播放步切换都会重建 `#unit-workspace.innerHTML` | 包住最终 V7/V6 渲染链，渲染完成后重新扫描和应用配置 |
| `#u-object-search.oninput` | 仅重建 `#u-object-list.innerHTML`，不调用完整工作台渲染 | 对目标 subtree 的 childList 观察也要覆盖 |
| `v7RefreshDocuments()` | 仅重建 `#u-canvas-body` | 重新登记表格、筛选栏与空状态，不复用旧 Element 引用 |
| `renderNav()` | 更新导航状态、图例、状态文字 | 静态标题覆盖应在它之后重放；不能以 active class 作为稳定 ID |
| `toggleAgent()` / `updateAgentCandidate()` | 重写智能体入口文字、候选工序、标题属性 | 文字配置需在变更后重新应用 |
| `renderAgentMessages/Source/History/Scope` | 创建回答、来源、历史和下拉选项 | 不能只扫描首次空对话窗 |
| `showV6Popup()` / `openModal()` | 临时构建对象窗与模态内容 | 仅后台预览在真实打开后可选择；展示态正常保留动态行为 |

建议结合显式 render 包装和 `MutationObserver(childList:true,characterData:true,subtree:true)`，对自身 patch 暂停观察/清空记录，避免重放循环。不观察所有 style 变动，三维选点标签每帧移动会造成无意义负载。

## 3. 圈中的横断面及四类场景 HUD 必须独立登记

| 组件根 | 来源 / 当前结构 | 推荐移动方式 |
|---|---|---|
| `.v6-linear-inset` | V6 包装渲染后插入 `#u-canvas-body`；道路为横断面，集电为纵断面 | 作为独立浮窗，单独 ID、位置和尺寸，不再只跟随整个 `.u-canvas-panel` |
| `.u-scene-caption` | `unitSceneFrame()` 内的说明块 | 独立位置；内部 span、strong、small 各段文字可编辑 |
| `.u-scene-tools` | 2D/3D、缩放、定位、复位按钮组 | 独立位置；可编辑按钮文字、title、aria-label，不改 data-u-action/data-v6-action |
| `.u-scene-options` | 基础剖切、构件展开或操作说明 | 独立位置；其中按钮保持原点击处理 |
| `.u-scene-bottom` | 模型性质/缩放等底部说明 | 独立位置或局部偏移，内部文本单独编辑 |
| `.u-canvas-head` | 模型区域标题、复位和 SS 专业切换 | 可作为独立的标题工具行 |

### 包含块与事件风险

`.v6-linear-inset` 自带 `clip-path`、阴影；`.u-canvas-panel` 等祖先存在裁切或 backdrop-filter。直接给嵌套子组件 `position:fixed`，未解除祖先包含块，会出现坐标看似正确却被父框裁切或相对父框移动的问题。

可采用两种清晰策略之一：

1. 祖先仍在原 DOM，局部组件使用父容器内的绝对定位与局部归一化坐标；对需要跨栏移动的组件额外解除祖先裁切和 fixed 包含块。
2. 为独立 HUD 使用受控 portal：先放占位点，把实际节点移动到一个全屏 overlay 根，记录原父节点、兄弟位置、原 style；业务重建前恢复节点，重建后再登记。不要复制节点并丢失事件。

若 portal 移出 `#unit-workspace`，`data-u-action` 按钮会失去其委托事件 `unitClick`，应在 portal 根将这些点击转发给原处理器一次。V6 的全局 `data-v6-action` 仍正常处理，不能重复转发造成双倍缩放。横断面本身目前仅含文字和 SVG，因此没有这一委托依赖。

**不能同时把父卡片与所有后代都当成 viewport 固定目标**。父卡片移动时，后代的视口绝对坐标不会跟随。需要显式区分父级布局与局部布局；通用 `mode:local` 不能只保存却不在应用逻辑里使用。

## 4. 所有文字的登记与修改

### 用文本节点，保留图标与业务结构

例如 `strong` 的内容可能是 `54<small>%</small>`；按钮可能包含 SVG 图标和 span。给它们整体赋 `textContent` 会删除单位、图标、span 和业务后代。

应登记每一个非空 **Text 节点**，配置通过 `nodeValue` 更新。树中可把多个文本节点归在同一个语义父组件下。`<svg><text>` 同样使用其文本节点，不插入 HTML span；颜色除 color 外需同步到 SVG fill，字号在 SVG viewBox 中的视觉尺寸要用实际预览评估。

除了正文，至少应支持：

- 标题、说明、对象名称、阶段名称、按钮名称、状态标签、数值、单位、表头与单元格。
- SVG `<text>`、`<tspan>`，例如路面结构、排水、附属、检测点。
- 表单 `placeholder`、元素 `title`、`aria-label`。
- 下拉选项显示文字。

必须排除 SCRIPT/STYLE/TEMPLATE/META 等代码内容、后台编辑器自身和三维 WebGL canvas。文字编辑只接受普通文本，不接受任意 HTML、脚本或 CSS。

### 下拉选项的业务 value 要固定

V7 多处 `<option>` 未显式写 `value`，其 value 默认为文字。若直接把“待审核”改名，筛选代码就会收到新词而找不到数据。首次登记时应把原 value 显式写回 `option.value`，之后只修改展示文字。导航按钮和操作按钮的 data-* 行为键同样不能随文字改变。

## 5. 稳定 ID：不能只用行号和 nth-child

推荐身份优先级：

1. 已有唯一 ID，如 `ag-input`、`v7-doc-status`。
2. 显式组件别名，如 `linear-inset`、`scene-caption`、`right-progress`。
3. 语义 data 属性，如 `data-u-object`、`data-u-step`、`data-u-type`、`data-v7-record`、`data-u-action`、`data-ag-action`。
4. 以上根节点内的稳定结构路径和文本节点序号。

必须剔除 active、selected、expanded、warning 等状态 class。不能把现有文字本身当 ID；改字后 ID 会变化。不能按表格第 1 行建立资料身份；筛选后第 1 行可能属于另一份资料。

对象目录、工序与资料身份例子：

```text
left-objects / object:RD-A02 / label / text:0
left-wbs / step:RD-08 / label / text:0
records-table / record:RD-A02-RD-08-D4 / status / text:0
linear-inset / svg / text:3
```

若现有资料行只有操作按钮携带 `data-v7-record`，扫描时应将该键提升为整行的语义锚点，但不更改原按钮行为。

### 静态文案与对象数据必须区分

“实际填报”“计划完成”等静态标签可以按工程/模块统一编辑；54%、RD-A02、已报工序、位置等动态值应带上对象身份。否则把 RD-A02 的 54% 改为 60%，再切到 RD-B01，会把后者也显示为 60%。工序相关知识摘要应带工序身份；不应以查看另一工序的结果覆盖旧工序的编辑。

建议后台显示当前作用范围（页面级 / 对象级 / 工序级），或提供专门数据配置；至少不得把通用路径覆盖伪称为真实项目数据更新。用户当前需要可编辑展示内容，不能据此生成现场填报、正式审批或验收通过结论。

## 6. 必要回归检查

1. 改顶部项目名，保存草稿后前端仍保持旧发布；发布后前端更新，且无后台编辑按钮。
2. 将红框横断面拖到模型右侧或底部；宽高变化不裁切 SVG，内部每一处文字可改。
3. 单独移动场景说明、工具组、剖切入口；原按钮仍只执行一次原动作。
4. 改“施工管理辅助”显示文字，data-u-task 不变，导航仍能工作。
5. 修改一个进度数值后切换对象，验证编辑不错误扩散到其他对象。
6. 搜索对象再恢复全部，编辑的对象名称仍匹配原对象。
7. 文档按类型/状态筛选，改过的单元格仍属于同一份资料。
8. 修改下拉显示文字，筛选 value 仍为原值。
9. 模拟播放触发重建后，文字和位置保持；现场填报比例不由浏览状态改写。
10. 展开智能体并编辑欢迎语、输入提示、按钮、来源标题；旧对话保留其范围和来源。
11. 导出前端 HTML 清理编辑边框与后台根，保留配置和原脚本；换浏览器仍显示定制内容。
12. 草稿导入拒绝任意选择器/HTML/脚本，前后台通信只接受预期 iframe、类型和 schema。

## 7. 当前实施结论

前后台分离是本轮核心结构变化。V8 的“把固定几张整卡放进页面里的布局控制台”不足以覆盖当前需求。V9 应把可编辑性绑定到语义组件、嵌套图窗和文字节点，而不是维护少量标题字符串。本文尚未审查待完成的 V9 runtime/admin 实现；完成后需按上述清单逐项核验，不将源码审计冒充浏览器实测。
