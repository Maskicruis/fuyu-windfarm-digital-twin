# 工程管理辅助

在「文档数据库」下打开「工程管理辅助」。首次进入会载入扶余一号演示，覆盖 27 个风机机位、1 座升压站、道路和集电线路。工序名称参考《扶余一号-项目全流程分解（按施工工序划分） 20260426.xlsx》。线路按六个演示区段组织。工期、资源、依赖、区段划分和费率为演示输入。

1. 在「工序与工作面」维护工作面、工序、最早开工日、前置关系和资源需求。在「共享资源」录入班组、设备、数量、使用费率和闲置费率。设备检修、天气和进场限制可录入为产能窗口或最早开工日。
2. 设定起算日期、当前进度日、目标工期和现场管理费。查看工序网络图，可切换全网或选中工序及直接上下游。蓝线按前置工序的实际或计划完工日追溯至全场完工节点。节点解释相对最早开工日的等待，并链接进度登记。甘特图区分已发生时段和预计续作时段。
3. 如遇设备停用，点击「登记资源停用」输入时间窗。修改进度、工序、费用或资源后会自动重排，网络标出改期节点，并与上次计算比较工期和费用。已完工工序的实际日期保留，已开工工序保留进度日前的记录，剩余工作从进度日或随后可用的时段安排。
4. 在「排程智能体」提问，例如“吊装设备停用以后，哪些工序改期了？接下来可先开哪些工作面？”智能体使用现有模型配置、候选方案和最近一次计算结果。草稿保存在当前运行地址的应用内存储，跨设备或更换端口可通过「导出计划 JSON」和「导入计划」迁移。

费用口径为工序固定成本、实际使用台班日费用、现场管理费和闲置台班日费用之和。现场管理费按 D0 到完工边界之间的天数计。闲置台班日按该方案资源占用的峰值数量，在该资源首末使用之间按每日期间可用数量封顶，再扣除已使用台班日。停用窗口内的停租计费假设适用于示例，现场租约与核算口径一致时才可用来估价。

排程按整数天安排后续工作，遵守完工后开工的依赖、最早开工日、同专业同工作面互斥及每日资源容量。起算日记为 D0，任务占用区间为 `[startDay, endDay)`。以多优先级串行排程搜索候选，在工期目标内比较总成本。搜索有界，未找到达标候选时会展示找到的最短工期并明确标记。交通转运、跨工作面干扰、审批、安质门槛等只有在输入为工序依赖、工期或资源窗口后才会参与计算。

第三方可通过组件现有 JSON 服务接入。默认端口为 8790，实际端口以 `workspace/data/component-service.json` 为准。

| API | 请求与响应 |
| --- | --- |
| `GET /api/v1/engineering/demo` | 返回演示输入，可作为导入模板。 |
| `POST /api/v1/engineering/solve` | 请求 `{"plan": {...}}`。返回方案、目标达成状态、工序日界、费用及资源统计。 |
| `POST /api/v1/engineering/review` | 请求 `{"plan": {...}, "question": "..."}`，可传 `priorPlan` 与 `selected` 来比较上版和当前方案。 |

成功响应沿用 `{ok, apiVersion, data}`。模式错误或依赖循环返回 HTTP 400。产能冲突或工期未达标是有效的计算结果，通过 `data.status` 区分。导出的计划 JSON 可直接作为 `plan`，或者重新导入界面。结果 JSON 的 `selected` 表示界面选中的候选。

进度输入使用顶层 `asOfDay`。未开工工序省略 `progress`，已完工填写 `{"startDay":0,"endDay":3}`，施工中填写 `{"startDay":3,"remainingDays":2}`。调用方可读取各工序的 `actualStartDay`、`actualEndDay`、`plannedStartDay` 和 `waitDays`。实际期间的资源使用按录入需求回算，费用仍是模型测算。
