# 1.3.2 长文档超时修复（Hotfix 1）

适用于已安装内置解析引擎的 SpecFlow 知识组件 1.3.1 / 1.3.2。

症状：长扫描件仍在处理或已保存大量页面，却出现 `Timed out waiting for result of task`。MinerU 3.4.5 默认等待整份文档的上限为 3600 秒；低速 CPU 解析较长规范可能正常超过该时间。

修复将默认整份文档等待上限设为 28800 秒（8 小时）。组件原有的连续 5 分钟无输出、15 分钟无新页面检测、进程终止和检查点恢复均保留。显式设置的 `MINERU_TASK_RESULT_TIMEOUT_SECONDS` 环境变量仍优先。

1. 首先运行完整版 EXE，完成资源安装。
2. 将压缩包解压，使 `SpecFlow-1.3.2-Hotfix-1` 文件夹位于 EXE 旁边。
3. 双击其中的 `Apply-Hotfix.cmd`。使用随包 Python，无需额外安装。
4. 在文档数据库中，对此前超时失败的文件点击「重解析」。失败任务会沿用匹配的页面检查点，不需要从第一页开始。已在运行的解析进程沿用启动时的参数；修复对后续启动的解析生效。

修复仅修改引擎启动入口和本机校验记录，并先备份旧文件至 `数据备份`。不修改 API 设置、对话或规范原件。再次执行可安全跳过已安装修复。
